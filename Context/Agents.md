\# AGENTS.md

\# Rice Mill Intelligence System — Agent Instructions

You are working on a practical rice mill operating memory system.

Do not treat this as a normal SaaS dashboard project.  
Do not treat this as a generic ERP.  
Do not build a fantasy AI accountant.

The product goal is:

\> A voice-first and photo-first rice mill operating memory that captures imperfect real-world data, turns it into confirmed ledgers, detects missing/mismatched entries, calculates stock/profit with evidence, learns from owner corrections, and prepares clean reports for the CA.

\#\# Core Product Philosophy

The owner should feel:  
\- I speak.  
\- I upload a photo.  
\- I confirm.  
\- The system remembers.  
\- The system warns me when something is missing or wrong.  
\- The system shows evidence for every answer.

The owner should NOT feel:  
\- I am using complicated software.  
\- I need to fill long forms.  
\- AI is guessing my business.  
\- I need to trust black-box answers.

\#\# Non-Negotiable Rules

1\. AI can capture and explain data, but AI cannot silently create truth.  
2\. Every important field must have source, status, confidence, timestamp, and audit trail.  
3\. Business calculations must be deterministic, not generated by the LLM.  
4\. If data is missing, save the entry as incomplete and create a task.  
5\. If data conflicts, mark it as disputed. Do not fake reconciliation.  
6\. Every AI answer must be backed by database entries, documents, or calculation functions.  
7\. Owner corrections must be stored in correction memory and reused later.  
8\. Government paddy, farmer/custom paddy, private paddy, rice, bran, broken rice, and expenses must not be casually mixed.  
9\. The interface must remain simple: speak, upload photo, ask, confirm.  
10\. Prefer boring practical reliability over clever AI features.

\#\# Data Status Model

Every important record or field should support statuses like:

\- draft  
\- ai\_extracted  
\- user\_confirmed  
\- system\_calculated  
\- incomplete  
\- disputed  
\- estimated  
\- reconciled  
\- locked  
\- exported

Never show one fake final number if data is incomplete.

Use confirmed / pending / disputed / estimated separation.

Example:  
\- Confirmed paddy stock: 3,240 qtl  
\- Pending paddy stock: 280 qtl  
\- Disputed paddy stock: 64 qtl  
\- Possible total: 3,584 qtl

\#\# Evidence Rule

No evidence, no confident answer.

Every answer should be generated from:  
\- confirmed events  
\- source documents  
\- calculation functions  
\- audit trail  
\- data completeness score

If data is incomplete, say so.

Bad:  
“Profit is low because bran price dropped.”

Good:  
“Profit appears lower mainly because average bran sale rate dropped from ₹1,520/qtl to ₹1,360/qtl. This is based on 8 confirmed bran sale entries. However, 3 milling batches are missing output data, so confidence is medium.”

\#\# Correction Memory Rule

When the owner corrects AI output, save the correction.

Examples:  
\- Document type correction  
\- Truck number correction  
\- Center/party/dealer name correction  
\- Bag count correction  
\- Handwriting/OCR correction  
\- Accepted exception reason

Use correction memory in future extraction and suggestions.

Do not fine-tune in v1. Store corrections in the database and use them as retrieval/context/rules.

\#\# First MVP Scope

Build the smallest loop that proves the product:

1\. Upload document  
2\. Store original file  
3\. AI classifies document type  
4\. AI extracts structured fields  
5\. User confirms/corrects  
6\. Save correction memory  
7\. Create business event  
8\. Update ledger/calculation  
9\. Detect missing/mismatched data  
10\. Answer simple questions with evidence

\#\# First Supported Workflows

1\. Truck sheet upload → AI extract → confirm → paddy inward draft  
2\. Voice paddy inward → confirm → save

\#\# Tech Stack Preference

Use a practical MVP stack:

\- Next.js for frontend and app routes  
\- TypeScript  
\- Tailwind CSS  
\- Supabase Postgres  
\- Supabase Auth  
\- Supabase Storage  
\- OpenAI API for structured extraction, vision, voice, and explanation  
\- Optional Google Vision OCR backup for bad handwriting  
\- Excel/PDF export utilities

Avoid unnecessary microservices in v1.

\#\# Coding Principles

\- Use typed schemas.  
\- Use Zod for validation.  
\- Do not trust raw AI output.  
\- Use structured outputs where possible.  
\- Keep business logic in deterministic functions.  
\- Store original documents.  
\- Store extracted fields separately from confirmed fields.  
\- Store every correction.  
\- Store audit logs for edits.  
\- Do not hard-delete business records.  
\- Prefer soft delete / reversal events / adjustment events.  
\- Create clear database migrations.  
\- Keep UI mobile-first and simple.

\#\# UX Principles

Main user actions:  
\- Speak  
\- Upload photo  
\- Ask  
\- Confirm

Avoid long forms.  
Use short confirmation screens.  
Show missing fields clearly.  
Show risky mismatches clearly.  
Use simple language.

Example:  
“I found 460 bags from Mallapur PPC. I am not sure about truck number. Please confirm.”

\#\# AI Behavior

AI should:  
\- Convert voice into structured drafts  
\- Classify documents  
\- Extract fields  
\- Ask for confirmation  
\- Explain calculations  
\- Search documents  
\- Summarize missing tasks  
\- Suggest what to check

AI should not:  
\- Silently update stock  
\- Finalize government confirmation  
\- Guess unreadable handwriting as truth  
\- Invent profit reasons  
\- Hide missing data  
\- Give answers without evidence

\#\# Build Priority

Priority order:  
1\. Correctness  
2\. Recoverability  
3\. Auditability  
4\. Owner trust  
5\. Simple UX  
6\. Fast pilot  
7\. Clean abstraction  
8\. Visual polish

Do not optimize for fancy UI before the capture-confirm-ledger-evidence loop works.

\#\# Definition of Done

A feature is not done when the screen looks good.

A feature is done when:  
\- Data is saved correctly  
\- Missing data is handled  
\- Corrections are stored  
\- Audit trail exists  
\- Calculation is deterministic  
\- Evidence can be shown  
\- User can recover from mistakes  
\- Export/report impact is clear
